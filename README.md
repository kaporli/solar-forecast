# solar-forecast

Hourly forecasts of Belgian aggregate solar production (Elia, "measured and upscaled") from open weather data
(Open-Meteo, ECMWF IFS), with PVDAQ system 2107 as a separate installation-level experiment.

- `docs/data-feasibility.md`: sources and what was verified.
- `docs/forecast-protocol.md`: the frozen protocol (issuance, targets, inputs, benchmarks).
- `docs/feature-contract.md`: every feature column, generated from `src/solar_forecast/features.py`.
- `docs/quality/`: coverage before and after cleaning, generated by the build.
- `docs/evaluation-protocol.md` (`config/evaluation.json`): frozen folds, test period, metrics and selection rules.
- `docs/evaluation/`: baseline and learned-candidate validation results, generated by `solar-data evaluate` and
  `solar-data compare`.
- `docs/model-selection.md`: candidates, the lock and the final-test procedure.
- `docs/evaluation/belgium-test.md`: the final test of the locked selection, run once.
- `docs/deployment.md`: runtime and measurements on the deployment worker.
- `docs/local.md`: the local view, per lattice point and province (`solar-data local belgium`).
- `artifacts/belgium/`: the deployment model, its manifest and parity fixtures (`solar_forecast.artifact`).
- `legacy/`: the 2024 student project, kept as it was.

## Commands

```
uv sync
uv run pytest                          # offline: contract and transformation tests
uv run solar-data fetch belgium        # snapshots: Elia ods032/ods209/ods210 and every needed weather run
uv run solar-data snapshot             # Elia ods209 (last 14 days) and ods210; scheduled four times a day
uv run solar-data snapshot --reconcile # every calendar month of ods209 history; scheduled monthly
uv run solar-data fetch pvdaq          # snapshots: PVDAQ 2107 files (checksums pinned) and weather runs
uv run solar-data local belgium        # the local view: data/local/ and data/feed/belgium-local.json; scheduled twice a day
uv run solar-data build belgium        # data/build/belgium-v1/{targets,features}.parquet, manifest, report
uv run solar-data build belgium --inputs data/datasets/belgium-v1.json   # rebuild from the pinned snapshots
uv run solar-data evaluate belgium     # baselines over the validation folds; the test period stays locked
uv run solar-data compare belgium      # learned candidates, ablation, selection rule, resources, interval check
uv run solar-data lock belgium         # config/lock-belgium.json, before any final-test score
uv run python -m solar_forecast.final_test belgium   # the final test, once; packages artifacts/belgium/
uv run tools/check_sources.py          # re-run the feasibility checks
```

Snapshots land in `data/raw/snapshots/` and `data/raw/objects/` (not committed) and are never overwritten; the dataset manifest in
`data/datasets/` lists each one with the SHA-256 of its payload and sidecar, so a rebuild from the same snapshots gives the same
content hashes.
